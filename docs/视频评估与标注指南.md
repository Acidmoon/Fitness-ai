# 视频评估与标注指南

本指南说明**收集什么视频、按什么要求拍、怎么标注、怎么出报告**。
工具链：`scripts/evaluate_videos.py`（批量评估）+ `scripts/annotate_video.py`（骨架叠加回看）。
判据数值本身见 `docs/动作评分标准.md`；本文只讲采集与评估流程。

## 1. 这批数据要回答什么

| 问题 | 需要的标注 | 报告里的指标 |
| --- | --- | --- |
| 关键点识别是否可用 | 只需机位与可用性 | 置信度、有效帧比例、缺失关键点 |
| 自动计次准不准 | 人工数出的次数 | MAE、完全一致率、误差 ≤1 次比例、偏差 |
| 错误判据会不会误报/漏报 | 每个错误码的有无 | 各错误码精确率、召回率、TP/FP/FN |
| 相位事件是否合理 | 不需要额外标注 | 相位序列合法率、完整周期数与计次不一致数 |

**不能回答**的：关键点绝对精度（需要人工标像素级关键点）与 2D 投影误差分离，
这两项排在后续任务 `cv-keypoint-accuracy-measurement`。

## 2. 采集硬性要求

| 项目 | 要求 | 原因 |
| --- | --- | --- |
| 格式 | `.mp4` / `.mov` / `.avi` / `.mkv` | 后端只接受这四种 |
| 体积 | 单个 ≤ **50MB** | 上传限制 |
| 分辨率 | 1080p（720p 可用，更低不建议） | MoveNet 输入为 192/256 方形，太小会丢细节 |
| 帧率 | 30fps | 采样按比例抽帧 |
| 采样帧率 | 默认 5fps，评估建议传 `--sample-fps 10` | 5fps 下一次 1 秒的重复只有约 5 个采样点，峰谷易漏 |
| 时长 | 每段 **5–10 秒**，包含 3–10 次重复 | 后端最多存 120 个采样帧（5fps ≈ 24 秒），过长会被截断 |
| 朝向 | **横屏**拍摄 | 手机竖屏视频的旋转元数据在 OpenCV 下处理不一致 |
| 机位 | 三脚架或靠墙固定；正侧方机位，镜头与动作平面平行 | 2D 角度依赖投影，斜拍会系统性低估幅度 |
| 构图 | 全身入镜，人物占画面高度 50–80% | 太远关键点精度下降，太近关节出框 |
| 光照 | 顺光或均匀光；避免逆光和强烈侧影 | 逆光会显著降低置信度 |
| 着装 | 贴身衣物，避免宽松遮挡关节 | 宽松衣物会让关键点漂移 |
| 画面 | 单人独占画面 | 多人同框时单姿态模型会跟错人 |

## 3. 采集清单

先拍基线组跑通流程，再补错误组与边界组。

**基线组（每个动作、每种机位）**

| 组 | 数量 | 内容 |
| --- | --- | --- |
| 俯卧撑·正侧 | 3 段 × 5–10 次 | 标准动作 |
| 深蹲·正侧 | 3 段 × 5–10 次 | 大腿至或低于平行 |
| 深蹲·正面 | 2 段 | 验证膝内扣 |
| 深蹲·45° | 2 段 | 验证非正侧机位下的表现 |

**错误组（每类 1–2 段，动作做明显）**

- 俯卧撑：不到位（半程）、塌腰、撅臀、手肘外展
- 深蹲：半程、膝内扣、躯干前倾
- 俯卧撑或深蹲：节奏忽快忽慢

**条件组**：正常光 / 逆光 / 暗光各 1 段；远景（人很小）1 段；半身出框 1 段；镜头抖动 1 段。

**边界组**：画面无人、两人同框、静止保持各 1 段——这些应判定为不可用或明确报错，而不是随便给分。

## 4. 目录与清单

建议结构：

```text
videos/
  manifest.csv
  pushup_side_01.mp4
  pushup_side_02.mp4
  squat_side_01.mp4
  ...
reports/
  eval-20260908-1530/
    report.md
    report.json
    annotated/
```

`manifest.csv` 模板（UTF-8，首行表头必须一致）：

```csv
file,exercise,expected_count,expected_errors,expected_usable,camera_angle,sample_fps,notes
pushup_side_01.mp4,俯卧撑,6,-,yes,side,,标准动作
pushup_side_02.mp4,俯卧撑,4,push_up_sagging_waist,no,side,10,故意塌腰
squat_front_01.mp4,深蹲,8,squat_knee_valgus,no,front,,故意膝内扣
```

| 字段 | 说明 |
| --- | --- |
| `file` | 相对视频目录的文件名（也可写绝对路径） |
| `exercise` | 动作名称或类型：`俯卧撑`/`push_up`、`深蹲`/`squat` |
| `expected_count` | 人工数出的有效次数；留空表示未标注 |
| `expected_errors` | 错误码列表，用 `;` 分隔；写 `-` 表示**明确没有错误**；留空表示未标注 |
| `expected_usable` | `yes`/`no`；留空表示未标注 |
| `camera_angle` | `side`/`front`/`45` 等，用于分组分析 |
| `sample_fps` | 该视频单独指定采样帧率；留空用命令行参数 |
| `notes` | 自由备注，会出现在报告逐条表格里 |

JSON 清单同样支持：数组或 `{"samples": [...]}`，字段名一致。

## 5. 标注规则

**计次（`expected_count`）**：只数**有效次数**，判据与算法一致——俯卧撑降到肩肘同一水平面并撑起、
身体保持平直才算一次；深蹲大腿到或低于平行并站直才算一次。判据细节见 `docs/动作评分标准.md`。
数的时候以完整周期为单位，半程不算。

**错误码（`expected_errors`）**：用规范代码，不用中文描述。

| 动作 | 可选错误码 |
| --- | --- |
| 俯卧撑 | `push_up_insufficient_range`、`push_up_sagging_waist`、`push_up_hip_pike`、`push_up_elbow_flare`、`push_up_body_twist`、`push_up_rhythm_instability` |
| 深蹲 | `squat_insufficient_depth`、`squat_knee_valgus`、`squat_forward_lean` |

塌腰与撅臀互斥：髋部低于肩踝连线记 `sagging_waist`，高于记 `hip_pike`，分不清就不标。

**可用性（`expected_usable`）**：`yes` 表示这段视频足以支撑可信评分（全身入镜、光线可辨、关键点稳定）；
`no` 表示应当判为不可用（人太小、出框、严重逆光、画面无人）。

**标注纪律**

- 每条标注都记录当时的 `rule_version`（报告会自动带上），跨版本标注不可直接比较。
- 至少 **20%** 的样本由第二人独立标注，报告里另行记录一致率；否则分不清"算法错"还是"标注不一致"。
- 标注时先看原视频独立数次数，再回看叠加视频，避免被算法输出带偏。

## 6. 运行与读报告

```bash
# 批量评估（可选 --annotate 同时产出骨架叠加视频）
python scripts/evaluate_videos.py videos/ --manifest videos/manifest.csv \
    --output reports/eval-20260908 --sample-fps 10 --annotate

# 单条回看
python scripts/annotate_video.py videos/pushup_side_02.mp4 -o out/pushup_side_02.mp4 \
    --sample-fps 10 --exercise 俯卧撑 \
    --angle left_shoulder,left_elbow,left_wrist
```

产物：`report.md`（人读）、`report.json`（机器读，含逐条原始指标）、`annotated/`（叠加视频）。

读报告的要点：

- **次数**：先看 `MAE` 与 `误差 ≤1 次比例`。机位合规的基线组目标是完全一致率 ≥80%、MAE ≤0.5；
  达不到先查采集质量（置信度、有效帧比例），不要急着改阈值。
- **错误码**：`support`（标注中出现次数）< 20 时只做失败案例分析，不宣称精确率/召回率。
- **可用性**：`false_usable`（该判不可用却给了分）比 `false_unusable` 更危险，优先修。
- **相位**：合法率应为 100%；`完整周期数与计次不一致` 说明相位机与计次口径有分歧，需要排查。

## 7. 样本量目标

| 目标 | 最小样本 |
| --- | --- |
| 每个动作每种机位的角度容差校准 | 30 次重复 |
| 每个动作的计次误差报告 | 100 次重复 |
| 单个错误码的精确率/召回率 | 20 个阳性样本 |

低于这些量级只能做定性描述，报告里要写明"样本不足，仅供参考"。
