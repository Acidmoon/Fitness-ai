# 错误动作识别设计

本文档记录当前后端错误动作识别的工程口径。错误识别不是替代标准度评分，而是在评分结果中补充可复现的动作问题证据。

## 输出结构

错误动作识别结果放在 `metrics.errors`。每个错误项包含：

- `code`：稳定错误代码，供 Web 和 Android 做结构化展示。
- `label`：面向用户的简短中文名称。
- `severity`：`minor` 或 `major`。
- `feedback`：可直接展示或写入训练记录的纠错建议。
- `evidence`：触发该错误的关键数值证据。

示例：

```json
{
  "code": "push_up_elbow_flare",
  "label": "俯卧撑手肘外展过大",
  "severity": "major",
  "feedback": "俯卧撑手肘外展过大，建议让上臂更靠近身体两侧，减少肩肘压力",
  "evidence": {
    "average_elbow_flare_angle": 58.2,
    "max_elbow_flare_angle": 64.0
  }
}
```

## 当前错误代码

| 动作 | 错误代码 | 识别证据 |
| --- | --- | --- |
| 俯卧撑 | `push_up_sagging_waist` | 肩-髋-踝身体线条偏差 |
| 俯卧撑 | `push_up_insufficient_range` | 最低点角度、角度行程、无效次数原因 |
| 俯卧撑 | `push_up_elbow_flare` | 髋-肩-肘夹角均值和最大值 |
| 深蹲 | `squat_knee_valgus` | 膝距相对髋距和踝距的内扣比例 |
| 深蹲 | `squat_insufficient_depth` | 最低点角度、角度行程、无效次数原因 |
| 深蹲 | `squat_forward_lean` | 躯干相对垂直方向的前倾角 |

## 模块边界

- `pose_error_detection.py` 负责错误规则注册、规则发现和证据构建。
- `pose_features.py` 继续提供通用几何工具，不写动作专属错误语义。
- `exercise_pose_scoring.py` 负责把 `metrics.errors` 接入评分响应，并把错误反馈合并到顶层 `feedback`。
- 规则阈值当前是 MVP 经验阈值，后续应通过样例视频和人工标注校准。

## 新增规则流程

错误动作规则应保持显式、可发现、基于规则，不应隐藏在评分编排函数或单个大型条件分支里。

当前注册入口是 `app/services/pose_error_detection.py`：

1. 为新动作或新错误写一个小型 detector，输入保持为 canonical keypoint frames、`PhaseSummary` 和 `ExerciseRule`。
2. detector 返回稳定 `code`、用户可读 `label`、`feedback`、`severity` 和可解释 `evidence`。
3. 在 `ERROR_RULE_DEFINITIONS` 注册 `exercise_type`、稳定 `code`、`label` 和 detector。
4. 用 `get_registered_error_codes(exercise_type)` 或 `get_error_rule_definitions(exercise_type)` 做发现和测试。
5. 为 unknown exercise 保持空列表，不应因为没有注册错误规则而中断评分。

新增规则时不要修改已有 error code 的语义。阈值、反馈文案或评分权重如果需要调整，应作为独立任务并配套回归测试。
