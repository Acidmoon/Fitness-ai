# 错误动作识别设计

本文档记录当前后端错误动作识别的工程口径。错误识别不是替代标准度评分，而是在评分结果中补充可复现的动作问题证据。

## 输出结构

错误动作识别结果放在 `metrics.errors`。每个错误项包含：

- `code`：稳定错误代码，供 Web 和 Android 做结构化展示。
- `label`：面向用户的简短中文名称。
- `severity`：`minor` 或 `major`。
- `feedback`：可直接展示或写入训练记录的纠错建议。
- `evidence`：触发该错误的关键数值证据。

示例：

```json
{
  "code": "push_up_elbow_flare",
  "label": "俯卧撑手肘外展过大",
  "severity": "major",
  "feedback": "俯卧撑手肘外展过大，建议让上臂更靠近身体两侧，减少肩肘压力",
  "evidence": {
    "average_elbow_flare_angle": 58.2,
    "max_elbow_flare_angle": 64.0
  }
}
```

## 当前错误代码

| 动作 | 错误代码 | 识别证据 | 口径来源 |
| --- | --- | --- | --- |
| 俯卧撑 | `push_up_insufficient_range` | 最低点角度、角度行程、无效次数原因 | 国标“未降至肩与肘同一水平面不计次” |
| 俯卧撑 | `push_up_sagging_waist` | 身体线偏差 + 髋部在肩踝连线**下方** | 国标“身体未保持平直” |
| 俯卧撑 | `push_up_hip_pike` | 身体线偏差 + 髋部在肩踝连线**上方** | 同上 |
| 俯卧撑 | `push_up_elbow_flare` | 髋-肩-肘夹角均值和最大值 | 工程判据（肩肘压力） |
| 俯卧撑 | `push_up_body_twist` | 左、右肩-髋-踝链角度差 | 国标“身体未保持平直”的扭转表现 |
| 俯卧撑 | `push_up_rhythm_instability` | 有效次数时长的变异系数（需 ≥3 次） | 工程判据，非国标 |
| 深蹲 | `squat_insufficient_depth` | 最低点角度、角度行程、无效次数原因 | ACSM 平行口径 |
| 深蹲 | `squat_knee_valgus` | 膝距相对髋距和踝距的内扣比例 | 工程判据 |
| 深蹲 | `squat_forward_lean` | 躯干相对垂直方向的前倾角 | 工程判据 |

具体角度与阈值见 `docs/动作评分标准.md`；本文件只描述错误判据的结构与边界。

## 塌腰与撅臀为什么必须拆成两个代码

国标只写了“身体未保持平直”，但下坠（塌腰）和上顶（撅臀）的纠正建议相反，混在一个代码里会让用户得
到无意义的提示。因此 `pose_features.extract_body_line_offset_samples()` 计算**带符号**的髋部偏移：
以肩→踝为体轴，偏移按肩踝跨度归一化，并用该轴的 x 分量符号规范化，使受试者头朝左或朝右不影响结论。

方向成立有物理前提：**体轴必须接近水平**（`|axis_y| <= 0.5 * |axis_x|`），图像 y 轴才近似重力方向。
站立、坐姿或机位不合规时该函数不返回方向证据，此时服务端退回到 `push_up_sagging_waist` 并在证据里标
`hip_offset_direction: "not_applicable"`，而不是凭投影几何凭空判出“撅臀”。

两个代码由同一偏差阈值触发（均值偏差 > 18° 报出，> 30° 为 major），但按偏移符号二选一，因此不会同时出现。

## 版本纪律

错误判据的语义变化必须随 `rule_version` 一起发布。`push_up` 从 v2 升到 v3 的内容是：
`push_up_sagging_waist` 由“塌腰或撅臀”收窄为只报塌腰，撅臀改由新增的 `push_up_hip_pike` 报告，
同时新增 `push_up_body_twist` 与 `push_up_rhythm_instability`。阈值与计次口径未变。
消费方展示时应使用响应里的 `label` 而不是自己按 code 硬编码文案，这样收窄不会造成误导。

## 模块边界

- `pose_error_detection.py` 负责错误规则注册、规则发现和证据构建。
- `pose_features.py` 继续提供通用几何工具（含带符号体轴偏移），不写动作专属错误语义。
- `exercise_pose_scoring.py` 负责把 `metrics.errors` 接入评分响应，并把错误反馈合并到顶层 `feedback`。
- 角度阈值已按官方口径校准（见 `docs/动作评分标准.md`），但**容差仍是工程估计**，需要真实样例与人工标注才能收敛。

## 新增规则流程

错误动作规则应保持显式、可发现、基于规则，不应隐藏在评分编排函数或单个大型条件分支里。

当前注册入口是 `app/services/pose_error_detection.py`：

1. 为新动作或新错误写一个小型 detector，输入保持为 canonical keypoint frames、`PhaseSummary` 和 `ExerciseRule`。
2. detector 返回稳定 `code`、用户可读 `label`、`feedback`、`severity` 和可解释 `evidence`。
3. 在 `ERROR_RULE_DEFINITIONS` 注册 `exercise_type`、稳定 `code`、`label` 和 detector。
4. 用 `get_registered_error_codes(exercise_type)` 或 `get_error_rule_definitions(exercise_type)` 做发现和测试。
5. 为 unknown exercise 保持空列表，不应因为没有注册错误规则而中断评分。

新增规则时不要修改已有 error code 的语义。阈值、反馈文案或评分权重如果需要调整，应作为独立任务并配套回归测试。
