# 动作评分标准

本文件回答一个问题：**某个动作"做得标准"到底按什么判**。它是工程口径，不是训练建议的替代品。

三处真相来源，按优先级：

1. 运行时生效值：`GET/POST /api/ai/records/{id}/pose-scoring` 响应里的 `metrics.rule`（阈值快照）。
2. 目录数据：`Exercise.standard.pose_scoring`（每行动作可自带标准，无需改代码）。
3. 代码默认值：`app/services/exercise_rules/<action>.py`（目录行没有该字段时的回退）。

本文件是这三者的可读投影；数字与 `tests/test_pose_scoring_standards.py` 的断言绑定，改代码不改文档会被测试或评审拦住。

## 口径来源（先说清谁规定的）

**俯卧撑——有国标。**《国民体质测定标准手册（成年人部分）》（国家体育总局）俯卧撑测试方法原文：

> 受试者双手撑地，手指向前，双手间距与肩同宽，身体挺直，屈臂使身体平直下降至**肩与肘处于同一水平面**，然后将身体平直撑起，恢复至开始姿势为完成 1 次，记录次数。测试时，如果**身体未保持平直**或身体未降至肩与肘处于同一水平面，该次不计数。测试限时 3 分钟。

原文核对：[国民体质监测项目介绍·俯卧撑](https://bjtyjsh.sgztcm.com.cn/info/detail/88)、[县区政府体质测试附件（同文本）](https://www.fxxq.gov.cn/xqq/file/2020-05-12/ff8080817203343b93001720893a5c33670.docx)。

**深蹲——没有国标项目，必须换口径。**《国民体质测定标准》成年人部分的力量类项目只有俯卧撑（男）、1 分钟仰卧起坐（女）、纵跳、坐位体前屈、选择反应时、闭眼单脚站立、握力，**不含深蹲**。因此深蹲采用 [ACSM 力量训练口径](https://www.ovid.com/jnls/acsm-healthfitness/abstract/10.1249/fit.0000000000000745~the-front-squat-exercise)：下蹲至大腿与地面平行或更低，起身至髋膝完全伸直方计一次。文档与 `criteria_source` 都写明了这一区别，避免被当成国家标准。

**六维权重与错误码语义**：见 `docs/标准度评分体系设计.md`、`docs/错误动作识别设计.md`，本文件不重复。

## 俯卧撑 `push_up-v3` 

角度定义：肩-肘-腕（左右各一条，取均值）；180° = 手臂伸直。

| 判据 | 生效值 | 官方/几何依据 | 容差理由 |
| --- | --- | --- | --- |
| 到位（bottom） | 肘角 ≤ **95°** | "肩与肘处于同一水平面" ⇒ 上臂近水平、肘角约 90° | 2D 关键点抖动留 +5°，不放宽到可判半程的程度 |
| 理想深度 `target_angle` | **90°** | 同上，官方位置直接对应值 | 用于深度维度评分而非计次 |
| 还原（top） | 肘角 ≥ **160°** | "恢复至开始姿势" = 双臂伸直（180°） | 留 −20°：侧视下完全伸直常测到 165–178° |
| 单次最小行程 | ≥ **60°** | 理想行程约 90°（180→90） | 拒绝"只下一半就起"的半程动作 |
| 有效帧下限 | ≥ 3 帧 | 工程参数 | 少于 3 个采样角无法构成周期 |
| 关键点置信度门 | ≥ 0.35（低置信提示 0.55） | 工程参数 | MoveNet 阈值，非国标 |
| 单次时长 | **300–12000 ms** | 工程参数（国标只规定测试限时 3 分钟） | 快于此视为弹动借惯性，慢于此视为停顿 |

无效一次会带原因码：`insufficient_depth`（未达水平面）、`incomplete_extension`（未伸直还原）、`insufficient_range`（行程不足）、`too_fast`、`too_slow`、`low_confidence` 。计数来源固定 `angle_peak_valley` 。

已实现的动作错误判据（对应官方"身体未保持平直"）：`push_up_sagging_waist`（塌腰）、`push_up_hip_pike`（撅臀）、`push_up_elbow_flare`（肘外展）、`push_up_insufficient_range`（幅度不足）、`push_up_body_twist`（左右失衡/身体扭曲）、`push_up_rhythm_instability`（节奏不稳）。

## 深蹲 `squat-v2` 

角度定义：髋-膝-踝（左右各一条）；180° = 腿伸直。

| 判据 | 生效值 | 依据 | 容差理由 |
| --- | --- | --- | --- |
| 到位（bottom） | 膝角 ≤ **100°** | 平行位膝角约 90–100°，取决于站距与踝背屈 | 取区间上沿 100° 作保守边界：宁可漏判也不把半程算有效 |
| 理想深度 | **95°** | 略低于平行的常见执行 | 用于深度维度评分 |
| 还原（top） | 膝角 ≥ **165°** | 30 秒坐站测试口径：必须完全站立方计一次 | 留 −15° 容差 |
| 单次最小行程 | ≥ **55°** | 理想行程约 75–85° | 拒绝浅蹲弹动 |
| 其余（置信度、有效帧、时长） | 同俯卧撑 | 工程参数 | 同上 |

深蹲错误判据：`squat_insufficient_depth`、`squat_knee_valgus`（膝内扣）、`squat_forward_lean`（躯干前倾）。

## 采集前提（不满足则数字无意义）

1. **正侧方机位**，镜头高度约在髋部，人物全程完整入镜（俯卧撑需肩、肘、腕、髋、踝；深蹲需髋、膝、踝）。
2. 相机roll（横屏倾斜）会直接破坏"肩肘同水平"的等价换算；深度与身体直线判据假设重力方向与图像 y 轴一致。
3. 侧视只投影单侧链，左右差被压平，因此 `left_right_symmetry` 维度与 `body_twist` 判据在纯侧视下证据有限——需要斜前方 30–45° 机位才能可靠评估。
4. 采样率默认 5 fps：单次动作快于 300 ms 会被判 `too_fast`，这是采样上限而非体能判断。

完整的拍摄清单、清单文件格式与标注规则见 `docs/视频评估与标注指南.md`。

## 明确不实现的判据

17 点 COCO schema 无法可靠支撑以下判据，**故意不做**，不要假装覆盖：

- 脚跟离地、足弓塌陷、膝过脚尖（需要足部/鞋面点位）。
- 肩胛骨收缩、颈椎中立（需要肩胛与面部额外点位）。
- 真实三维蹲深与躯干旋转角（单目 2D 只能给投影近似）。

## 版本与变更规则

1. 标准以 `rule_version` 标识（当前 `push_up-v3`、`squat-v2`）；**改任何阈值或错误判据必须同时 bump 版本**，否则新旧分数无法区分。
2. 逐行改口径：编辑该动作的 `Exercise.standard.pose_scoring`（含 `rule_version`、`criteria_source`），不必改代码；改完重跑 seed 使库内数据同步。
3. `analysis.rule_version`（目录展示字段）由注册表反查生成，禁止再写死字符串。
4. 阈值调整必须有回归样例支撑：至少一条"按新口径有效"与一条"按新口径无效"的样例进 `tests/fixtures/cv_evaluation_samples/samples.json` 。
5. 现行数值是**官方判据 + 2D 测量容差**的组合，容差是工程估计，尚未用真实标注样本校准；这一步排在 `cv-evaluation-real-samples`（见 `DEV/LOOP_QUEUE.md`）。

## 已知偏差与待校准项

- `v1 → v2` 的主要变化是收紧"到位"和"还原"判据：俯卧撑 `up_angle` 150→160、`min_range` 45→60；深蹲 `down_angle` 115→100、`up_angle` 155→165、`min_range` 40→55 。
- 因此 **v2 起的自动次数普遍低于 v1**，这是修正"半程也算一次"的预期结果，不是回归；比较历史分数时必须先看 `analysis_rule_version` 。
- 容差目前来自工程估计；等真实样例与人工标注就位后，应给出"AI 次数 vs 人工次数"的误差分布，再决定是否收紧到官方理想值（俯卧撑 90°、深蹲平行位）。

### `push_up-v3` 相对 v2 的变化

只改变错误判据，不改变阈值与计次：`push_up_sagging_waist` 从“塌腰或撅臀”收窄为只报塌腰，撅臀改由新 code `push_up_hip_pike` 报告；新增 `push_up_body_twist`（躯干扭转）与 `push_up_rhythm_instability`（节奏不稳，工程判据）。计次、次数与分数口径不变，因此版本从 v2 升到 v3。
