# 动作分析模块化设计

本文档记录后端动作分析模块的当前边界和后续新增动作的适配方式，避免把所有动作逻辑继续堆到一个评分函数里。

## 第一性原理结论

动作分析的稳定扩展依赖清晰的数据流，而不是在 API 层或单个评分函数里不断增加条件分支。

当前后端应保持如下分层：

```text
HTTP API
  -> pose_analysis_service
  -> video_pose_analysis / pose backend
  -> canonical keypoint frames
  -> pose_features
  -> exercise_rules/<action>
  -> repetition_counter / phase detector
  -> exercise_pose_scoring
  -> record persistence
```

## 当前模块职责

| 模块 | 职责 | 不应承担 |
| --- | --- | --- |
| `app/api/ai.py` | HTTP 入参出参、鉴权、HTTP 错误码映射 | 视频推理细节、Job 状态机、动作算法 |
| `app/services/pose_analysis_service.py` | 姿态分析用例编排、视频可用性校验、Job 状态更新、响应构建 | 具体动作评分规则 |
| `app/services/video_pose_analysis.py` | 打开视频、调用姿态后端、压缩可存储的关键点结果 | 动作次数、动作质量评分 |
| `app/services/pose_features.py` | 关键点索引、置信度过滤、关节角度、角度序列抽取 | 动作专属阈值和评分 |
| `app/services/exercise_rules/base.py` | 动作规则协议、通用阈值阶段摘要、评分参数 | 具体动作的大段状态机 |
| `app/services/exercise_rules/repetition_counter.py` | 通用 `peak -> valley -> peak` 峰谷次数统计和无效次数原因 | 俯卧撑或深蹲专属动作语义 |
| `app/services/exercise_rules/pushup.py` | 俯卧撑关键点、阈值、阶段检测适配 | 其他动作逻辑 |
| `app/services/exercise_rules/squat.py` | 深蹲关键点、阈值、峰谷计数适配 | 其他动作逻辑 |
| `app/services/exercise_pose_scoring.py` | 评分编排、pose 数据校验、评分结果与记录适配 | 视频推理和 HTTP 错误码 |

## 新增周期型动作流程

1. 在 `app/services/exercise_rules/<action>.py` 新增动作规则类或规则实例。
2. 配置 `aliases`、`required_keypoints`、`joint_triplets`、`down_angle`、`up_angle`、`target_angle`、`min_range`。
3. 如果动作是标准周期动作，复用 `count_peak_valley_repetitions()` 生成 `valid_reps` 和 `invalid_reps`。
4. 如果动作需要专属阶段名称，像俯卧撑一样在动作模块内实现小型 phase detector，但仍复用通用次数统计。
5. 在 `app/services/exercise_rules/registry.py` 注册规则。
6. 在 `tests/test_exercise_pose_scoring.py` 或独立测试文件中加入有效次数、无效次数、低置信度、幅度不足样例。

## 当前计数证据格式

`repetition_counter.py` 会返回：

- `valid_reps`：完整且满足阈值的次数。
- `invalid_reps`：检测到周期趋势但未满足标准的次数。
- `reasons`：无效原因，例如 `insufficient_depth`、`incomplete_extension`、`insufficient_range`、`too_fast`、`too_slow`、`low_confidence`。
- `count_source`：当前为 `angle_peak_valley`。

评分响应应继续暴露 `auto_count`、`count_source`、`metrics.valid_reps` 和 `metrics.invalid_reps`，确保前端和后续评估材料可以解释每一次计数。

## 非周期型动作

平板支撑、平衡测试等动作不应强行使用峰谷次数统计。

这类动作应新增专属规则，输出持续时间、稳定性、关键点漂移、置信度和失败原因，并复用 `PoseScoringResponse` 的 `metrics` 字段保存证据。
